# 실행 가능한 학교·전투 프로토타입

## 실행

Unity 6000.3.7f1로 `UnityProject/`를 열고 `Assets/Scenes/School.unity`에서 Play를 누른다. 학교와 전투는 `School.unity`, `Battle.unity`로 분리되어 있다. 두 씬은 Build Settings에 등록되어 있다.

메뉴 `HongikIngan/Create prototype scenes`는 누락된 프로토타입 씬과 경제 설정만 생성하며 기존 씬을 덮어쓰지 않는다. 에디터 배치 빌드 진입점은 `HongikIngan.Editor.PrototypeBuilder.Build`, 규칙 검사 진입점은 `HongikIngan.PrototypeChecks.Run`이다.

## 플레이 방법

### School 화면 배치와 학생 드래그

`HongikIngan/Apply School reference layout` 메뉴는 기존 School 씬에 편집 가능한 `SchoolCanvas`를 한 번 배치하고 저장한다. 이미 배치된 Canvas는 덮어쓰지 않으므로 이후 위치·색상은 Hierarchy와 Inspector에서 수정할 수 있다. 상단에는 자원·칠판·모집·펫, 중앙에는 학생과 책상, 오른쪽에는 시너지, 하단에는 책 형태의 상세 정보와 리롤·전투 버튼을 둔다.

학생·모집 후보·펫·유물의 그림 영역은 빈 사각형이다. 이미지 생성이나 외부 일러스트 없이 UI Image 도형만 사용한다. 시너지 책은 표지·책등·페이지를 별도 도형으로 표현하며, 학생이 보유한 시너지 수만큼 표시한다. 기본 화면은 다섯 책상 위치를 보여 주되, 실제 배치 가능 인원은 기존 경제 설정을 따른다.

학생을 누른 채 끌면 학생 표시가 잡은 위치를 유지하며 커서를 따라 움직인다. 사용 가능한 빈 책상에 놓으면 그 자리에 배치하고, 다른 학생의 책상에 놓으면 서로 교환한다. 확장 전 책상이나 화면 밖에 놓으면 원래 자리로 돌아온다. 창 포커스를 잃거나 입력이 잠겨도 드래그를 취소한다. 책상·책은 학생 표시와 분리되어 드래그 중에는 움직이지 않으며, 배치 확정 후 책은 해당 학생의 시너지에 맞춰 갱신된다.

교실의 책상 배정은 `PrototypeRun`의 별도 매핑에 보존하므로 중간 빈자리를 유지할 수 있다. 판매 시 다른 학생을 앞으로 당기지 않고, 새 영입 학생은 첫 빈 책상에 배정한다. 전투 진입 시에는 책상 순서대로 학생 목록을 정렬하되 빈 책상은 전투 참가자로 넘기지 않는다. 전투 후 교실에서는 저장된 책상 배정을 사용한다.

메뉴 적용 시 UI 참조·책 형태·빈 이미지와 기존 프로토타입 규칙을 검사한다. Play Mode에서는 `HongikIngan/Verify School cursor drag (Play Mode)`로 커서 이동량 반영과 잘못된 드롭의 복귀를 확인할 수 있다. 실제 마우스로 학생 이동·교환, 모집·학습·판매, 펫 선택 및 사운드 팝업도 확인해야 한다. 검사 메뉴 제공은 검사 통과를 뜻하지 않는다.

### 기존 게임 조작

- 학생 카드를 드래그하여 순서를 바꾸고 클릭하여 학습·판매를 선택한다.
- 일반 모집의 학생 정보를 확인하고 영입한다. 공간 부족 시 교체 버튼의 얼굴·이름 목록에서 기존 학생을 판매하거나 임시 책상 확장을 이용한다.
- 펫은 클릭 시 먼저 결제된다. 최고급을 포함해 한 명만 선택할 수 있다. 포기는 환불 없이 후보 전체의 사진을 받는다.
- 펫 선택 중 교체 버튼을 누르면 얼굴·이름만 표시한 목록에서 판매할 학생을 선택할 수 있다. 일반 리롤·전투·학습 입력은 잠긴다.
- 사진은 같은 학생도 누적된다. 일반 모집에서 구매하지 않은 학생은 사진을 주지 않는다.
- 리롤은 20부터 시작해 20씩 증가한다. 구매 칸은 다음 리롤이나 전투 승리 후 교실 복귀까지 비워 둔다.
- 전투 버튼을 누르면 리롤 비용이 초기화되고 별도 전투 씬으로 이동한다. 배치 후 합동 공격 버튼으로 슬롯별 계산을 확인한다.
- 보스를 처치하면 교실로 복귀하며 다음 스테이지를 준비한다. 3턴까지 처치하지 못하면 다시 시작한다.
- 학교의 새 게임 버튼으로 현재 진행을 초기화할 수 있다. 학생을 모두 판매하고 재화를 소진한 경우에도 새로 시작할 수 있다.

## 구현 구조

| 경로 | 책임 |
| --- | --- |
| `Assets/Scripts/School/` | 경제 설정, 임시 콘텐츠, 학교 거래와 진행 상태 |
| `Assets/Scripts/Combat/` | 순차 계산, 타깃 전략, 키워드, 반응·교환 재행동, 승패 |
| `Assets/Scripts/UI/` | 학교·전투·오디오 설정 화면 |
| `Assets/Scripts/Prototype/` | 씬 간 진행 상태, 실행 검증 진입점 |
| `Assets/Scripts/Audio/` | 지속 SoundManager와 FMOD 연결 코드 |
| `Assets/Resources/PrototypeEconomy.asset` | 단일 경제 설정 에셋 |

역할군은 표시용이다. 데미지는 float로 발생 순서대로 계산하고 매 단계 갱신하며, 다음 턴 시작에 0으로 초기화한다. 반응 액션도 다른 반응을 발생시키고 위치 교환 시 새 슬롯의 작은 번호부터 재행동한다. 임의 연쇄 상한은 없다. 무한 콤보가 가능한 콘텐츠는 사후 조정 대상이며 기본 샘플은 진행 가능한 조합으로 구성했다.

## 임시 콘텐츠와 범위

처음부터 플레이할 수 있도록 시작 학생 1명과 재화 160, 학생 18명, 유물 6종을 넣었다. 얼굴은 색상과 기호로 표시하는 대체 이미지다. 경제 에셋에서 가격·보상·리롤·책상 확장 비용과 테스트용 보스/폴라로이드 수치를 조정할 수 있다. 캐릭터와 유물 원본은 `PrototypeContent.cs`의 임시 카탈로그이며 정식 콘텐츠 제작 도구가 아니다.

현재 임시 밸런스: 학년별 영입 30/60/90, 학습 20/40/60, 판매 15/30/45; 유물 30; 책상 확장 40; 보스 기본 체력 450 및 스테이지당 1.65배; 사진당 데미지 10; 승리 보상 70부터 스테이지당 +15. 실제 운영 수치로 확정한 것은 아니다. 펫 비용은 합의된 30/50/100/60이다.

활성 부활동은 샘플로 2명 이상일 때 인원당 데미지 +20을 준다. 콘텐츠 컨셉 문서의 각 부활동별 고유 효과 전체를 구현한 것은 아니다. 개별 스킬은 더하기·곱하기·다음 아군 키워드·보스 약화·재화 획득과 아군 액션 반응을 시연한다. 전투 종료 시 학생 키워드를 정리하는 것은 이번 프로토타입의 임시 운영 방식이다.

## 오디오

[FMOD 설정 안내](Audio%20Setup.md)를 따른다. 사용자가 설치를 보류했으므로 FMOD 패키지와 banks는 포함하지 않는다. 현재 실행에서는 소리를 재생하지 않으며 BGM/SFX/Voice의 볼륨·음소거 조절과 저장, 씬 유지 기능을 제공한다.

패키지·banks 설치 후 `HONGIK_FMOD`를 활성화하면 실제 FMOD 이벤트 경로를 사용한다. 프로토타입 연결 경로는 `event:/BGM/School`, `event:/BGM/Battle`, `event:/SFX/Beam`, `event:/Voice/Chant`다. 실제 제작한 이벤트 이름에 맞춰 변경할 수 있다.

## 검증

Unity 6000.3.7f1 컴파일과 자동 규칙 검증 2,219개 assertion을 통과했다. 학교 결제·후보·사진·슬롯·재영입, 3턴 승패·정확히 0 처치, 계산 순서와 표시, 키워드 8조합과 4096스택, 교환 및 반응 연쇄를 검사한다. 반응 연쇄 검사는 무한 iterator의 일부만 검사한 뒤 중단한다.

Windows 일반 빌드와 실제 실행 파일의 학교→전투→학교 자동 검증도 통과했다. 보스 처치 후 다음 스테이지 진행, 단일 SoundManager 유지, BGM 볼륨과 Voice 음소거 보존을 확인했다. 로그는 로컬 `Logs/PrototypeChecksFinal.log`, `Logs/PrototypeBuildFinal.log`, `Builds/SmokeRelease/result.txt`에서 확인한다. 이 생성물은 Git에 포함하지 않는다.

실제 창에서 학교 화면이 표시되는 것을 확인했지만 Windows 보안 창이 입력을 가려 수동 클릭·드래그 검증은 완료하지 못했다. 별도 네트워크 플레이 기능은 없으며, 보안 창을 사용자가 닫은 뒤 교체 패널·새 게임·사운드 조절과 전투 버튼의 수동 인수 검증이 남아 있다.

게임 시작 인수 `--prototype-smoke --smoke-output <폴더>`는 실제 학교→전투→학교 씬 전환과 SoundManager 유지 검증을 실행하고 결과를 `result.txt`에 기록한다. 테스트에 한해 보스 체력을 1로 낮추고, 테스트 종료 때 변경한 오디오 설정을 복구한다. 숨김 창의 스크린 캡처는 검게 출력될 수 있어 시각 검증은 실제 게임 창에서 별도로 수행한다. FMOD 실제 재생은 설치 보류로 검증 대상에서 제외했다.

전투 화면은 [전투 UI 편집 안내](Battle%20UI%20Editing.md)의 씬 저장 uGUI 구조를 사용한다. BattleCanvas/Layout에서 개별 슬롯과 화면 요소의 RectTransform을 직접 조절할 수 있다.
