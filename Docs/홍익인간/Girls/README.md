# 마법소녀 작성 서식

[Girl%d.jsonc](Girl%25d.jsonc)를 복사해 `Girl1.jsonc`, `Girl2.jsonc`처럼 작성한다. `%d`는 정수 자리이며 파일명·`girlId`·스킬/규칙 ID를 함께 바꾼다. 캐릭터마다 하나의 파일을 사용한다. 주석을 허용하는 유사 JSON(JSONC) 문서로, 게임에서 직접 로딩하지 않는다.

## 작성 순서

공통 효과는 [전체 시너지 효과 목록](synergy.md)과 [키워드 효과 목록](keywords.md)을 참조한다. 두 문서에는 Girl0–Girl11 구현과 사용자 확인 내용을 반영했으며, 아직 구현되지 않은 기획은 별도로 표시한다. 캐릭터별 확정 수치와 구현 범위는 [Girl0–Girl11 전투 구현](../Girl%20Battle%20Implementation.md)을 따른다.

1. 이름·소개·학년·표시 역할군·시너지를 적는다.
2. 스킬을 자연어로 설명하고 트리거, 조건, 효과 순서, 대상과 빈 대상 처리를 구체화한다. 조건이 없으면 `없음`, 적용되지 않는 설명은 `해당 없음`이라고 쓴다.
3. 스킬 변수의 초기값과 단위, 강화할 변수 하나, 강화값 대체 공식을 적는다. 예: `n은 강화 후 횟수, 100 + 80 * n`은 100 → 180 → 260이며 매번 결과로 교체한다. 이 수치는 설명용이다.
4. 새 키워드에만 소모성·중첩 가능·휘발성 여부를 각각 명시한다. 기존 키워드를 재사용하면 같은 ID로 참조한다. 새 키워드가 없으면 `keywordDefinitions`를 `[]`로 둔다.
5. 기본 행동·강화·조건 불충족 사례를 실제 기대값까지 적는다. 위치 교환이나 반응을 사용하면 재행동·연쇄 사례도 추가한다.
6. 미정 항목은 `null` 또는 `openQuestions`로 남긴다. 구현 가능한 항목을 확정한 뒤 `status`를 `ready`로 바꾼다.

체력·방어력·치명타·속도·캐릭터별 가격은 추가하지 않는다. 가격은 학년별 공통 경제 설정을 사용하고 역할군은 표시 용도다. 같은 소녀의 중복 영입은 허용하지 않으며, 계약 해제 후 재영입하면 강화는 초기화된다. 반응 연쇄에 임의 횟수 제한을 추가하지 않는다. 규칙은 [속성 정의](../Magical%20Girl%20Attributes.md)와 [전투 기획](../Game%20System%20Design.md)을 따른다.

## AI에게 일괄 구현을 요청할 때

`Girls/`의 `ready` 파일을 대상으로 구현하도록 요청한다. AI는 먼저 ID 중복, 참조 누락, 미정 값, 강화 공식과 예시의 모순, 대상 선택·효과 순서를 검사하고 차이를 보고해야 한다. 설계가 확정되지 않은 항목은 임의로 완성하지 않는다. 작성된 인수 예시를 실제 테스트로 옮긴다.

현재 `PrototypeContent.cs`는 단일 `ActionKind`, 단일 수치, 제한된 반응과 부활동·성격·특수 시너지를 가진 임시 카탈로그다. 이 서식의 복수 효과·독자적인 강화 공식·새 대상 전략·새 키워드가 모두 이미 지원되는 것은 아니다. AI는 파일들을 단순 치환하기 전에 필요한 런타임 확장과 공용 계약 영향을 정리해야 한다. `girlId`를 영구 ID로 사용하고 목록 번호로 새 ID를 생성하지 않는다. 지역·직업 등 다른 시너지 분류가 필요하면 `notes`에 의도를 적고 기존 분류와 매핑을 확정한다.

실제 콘텐츠는 사용자가 복사·작성한 후 구현한다. 이 서식의 공란이나 예시는 새 마법소녀를 추가하라는 지시가 아니다.
