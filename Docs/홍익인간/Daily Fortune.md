# 오늘의 운세

2026-11-06 사용자 요청과 추가 확인에 따라 기존 유물 구매·보유·전투 효과를 대체한다. [교실 시스템](Classroom%20System%20Design.md), [시너지 목록](Girls/synergy.md)의 유물 관련 규칙보다 이 문서를 우선한다.

## 하루와 리롤

- 하루는 게임의 스테이지다. 새 게임과 전투 보상 수령 후 다음 날 학교 복귀 시 운세는 미선정 상태이며 리롤 기본 비용은 20이다. 현실 날짜는 사용하지 않는다.
- 기존 유물 UI 안에 운세 설명 텍스트만 표시한다. 별도 구매, 소장 목록, 사물함 위 누적 표시는 없다.
- 리롤 비용을 결제하면 아래 가중치로 결과 하나를 추첨한다. 같은 결과도 다시 나올 수 있다. 기본 비용은 성공할 때마다 20 증가하고 다음 날 초기화한다. 할인은 결제 시점의 현재 운세를 기준으로 계산하며 소수 비용은 올림한다.
- 0.04초 간격으로 텍스트를 바꾸다가 실제 경과 시간 0.8초 후 결과를 표시하고 즉시 적용한다. 연출 중 버튼과 교실 거래·전투 진입을 잠근다. 중복 콜백은 추가 결제하지 않는다.
- 현재 운세 하나만 유지한다. 다시 뽑으면 기존 지속 효과를 교체한다. 이미 지급한 에너지와 영구 강화는 회수하지 않는다. 다음 날에는 지속 효과만 초기화한다.
- 펫 후보 선택 중에는 리롤할 수 없고, 리롤은 펫 제안·사진·보유 학생을 바꾸지 않는다.

## 귀염둥이

기존 최고 단계 하나 적용 규칙과 1·3단계는 유지한다.

- 5명: 운세 추첨에서 꽝을 제외하고 효과 두 배.
- 7명: 위 운세 효과와 기존 아군 소모성 키워드 소모 방지.
- 9명: 모든 비용 공짜!. 상점 여부와 관계없이 모든 비용이 0이며, 현재 비용 항목인 운세 리롤·펫 모집·보충 학습·책상 확장을 모두 포함한다. 최고 단계 규칙에 따라 5·7단계 효과는 추가로 누적하지 않는다.

운세 효과 배수는 리롤 결제 시점의 귀염둥이 단계로 고정한다. 시너지 운세의 자기 참조를 방지하고 결과 표시와 적용을 일치시킨다. 두 배는 수치에 적용한다: 할인 50%→100%, 데미지 ×2→×4, 에너지 100→200, 시너지 +1→+2, 강화 1회→2회(1회형 상한 유지), 보상 ×1.5/2/10→×3/4/20. 시너지 모집 전환은 이진 효과이므로 추가 후보·추가 결제를 만들지 않는다.

## 구현 및 검증 진입점

- `PrototypeContent.cs`: 16종 텍스트·가중치와 꽝 제외 추첨.
- `PrototypeRun.cs`: 현재 운세·추첨 잠금·일일 초기화·가격·영구 지급·보상 스냅샷.
- `BattleSynergies.cs`, `CombatEngine.cs`: 귀염둥이 변경·가상 시너지·최종 데미지.
- `SchoolScreen.cs`: 0.8초 연출과 버튼 잠금. 기존 씬 바인딩을 보존하기 위해 UI 필드의 `relic` 이름은 호환용으로 남긴다. 유물 데이터와 구매 API는 제거했다.
- Editor 메뉴 `HongikIngan/Apply daily fortune UI`: 기존 씬의 운세 카드만 갱신하고 참조·규칙 검사.
- `HongikIngan.Editor.PrototypeBuilder.BuildFortune`: 규칙 검사 후 Windows 빌드. 플레이어의 `--school-economy-smoke --smoke-output <폴더>`로 실제 버튼·시간·씬 왕복을 확인한다.
